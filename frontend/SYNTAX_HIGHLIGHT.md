# Система подсветки синтаксиса

## Обзор

Система подсветки синтаксиса для русских текстов в редакторе документов. Подсветка работает на основе морфологического анализа слов и раскрашивает их в соответствии с частями речи.

## Архитектура

### Компоненты

1. **DocumentEditor.jsx** - главный компонент редактора с интегрированной подсветкой
2. **utils/syntaxHighlightValidation.js** - утилиты валидации и защитные механизмы
3. **services/morphology.js** - API для морфологического анализа
4. **__tests__/SyntaxHighlight.test.js** - автоматические тесты

### Поток данных

```
Пользователь печатает текст
    ↓
DocumentEditor извлекает русские слова (regex)
    ↓
Отправка на API морфологического анализа
    ↓
API возвращает {слово: часть_речи}
    ↓
Валидация данных (syntaxHighlightValidation)
    ↓
ProseMirror плагин создает декорации
    ↓
Слова подсвечиваются цветами
```

## Защитные механизмы

### 1. Самопроверка при загрузке модуля

При импорте `DocumentEditor.jsx` запускается функция `runSyntaxHighlightSelfCheck()`:

```javascript
// Проверяет:
// - Все части речи имеют валидные HEX цвета
// - Регулярное выражение работает корректно
// - Функции валидации работают правильно
// - Позиции декораций вычисляются корректно

// Если хоть одна проверка не прошла - подсветка отключается
```

### 2. Валидация данных на всех уровнях

**Входные данные от API:**
- Проверка типа (должен быть объект)
- Проверка на пустоту
- Валидация каждой записи (слово и тег - строки)

**Позиции декораций:**
- `from >= 0 && to >= 0` - неотрицательные
- `from <= to` - начало перед концом
- `to <= docSize` - в пределах документа

**Цвета:**
- Все цвета в формате HEX (#RRGGBB)
- Проверка существования цвета для каждой части речи

### 3. Graceful Degradation

Если что-то идёт не так, система **не ломает редактор**, а просто отключает подсветку:

```javascript
try {
  // Попытка создать декорацию
} catch (error) {
  console.error('[SyntaxHighlight] Error:', error);
  return DecorationSet.empty; // Возвращаем пустой набор декораций
}
```

### 4. Логирование

Все критические операции логируются с префиксом `[SyntaxHighlight]`:
- Успешное создание плагина
- Ошибки валидации
- Невалидные позиции
- Отсутствующие цвета

## Как работает плагин

### Инициализация

```javascript
// Плагин добавляется ВСЕГДА при создании редактора
// Он читает данные из highlightDataRef.current
const syntaxPlugin = new Plugin({
  key: new PluginKey('syntax-highlight'),
  state: {
    init() {
      return DecorationSet.empty;
    },
    apply(tr, oldState) {
      // Проверка и создание декораций
    }
  }
});
```

### Оптимизации

1. **Избегание лишних пересчётов:**
   ```javascript
   // Если документ не изменился и нет флага forceUpdate - 
   // возвращаем старые декорации, просто перемаппив их
   if (!tr.docChanged && !tr.getMeta('forceUpdate')) {
     return oldState.map(tr.mapping, tr.doc);
   }
   ```

2. **Кэширование анализа:**
   - Каждое слово анализируется только один раз
   - Повторные вхождения используют закэшированный результат

3. **Дебаунс анализа:**
   - Анализ запускается через 500ms после остановки печати

## API для разработчиков

### Добавление нового цвета для части речи

1. Откройте `utils/syntaxHighlightValidation.js`
2. Добавьте цвет в `POS_COLORS`:
   ```javascript
   export const POS_COLORS = {
     // ...
     newPOS: '#FF00FF', // Ваш новый цвет
   };
   ```
3. Добавьте тест в `__tests__/SyntaxHighlight.test.js`
4. Обновите таблицу в этой документации

### Изменение регулярного выражения для слов

**⚠️ ВАЖНО:** Не меняйте напрямую в коде плагина!

1. Откройте `utils/syntaxHighlightValidation.js`
2. Измените `WORD_REGEX`:
   ```javascript
   export const WORD_REGEX = /ваше_новое_выражение/g;
   ```
3. Добавьте тесты для нового выражения

### Отключение подсветки

```javascript
// В DocumentEditor.jsx, в начале компонента:
const syntaxHighlightEnabled = false; // или получите из настроек

// Передайте в MilkdownEditor:
<MilkdownEditor 
  syntaxHighlightEnabled={syntaxHighlightEnabled}
  // ...
/>
```

## Тестирование

### Запуск тестов

```bash
npm test SyntaxHighlight.test.js
```

### Ручное тестирование

1. Откройте редактор документа
2. Включите подсветку синтаксиса (кнопка "Подсветка")
3. Введите текст на русском языке
4. Проверьте консоль на наличие ошибок с префиксом `[SyntaxHighlight]`

### Проверка самодиагностики

Откройте консоль браузера при загрузке редактора. Должны быть логи:
```
[SyntaxHighlight] Self-check passed ✓
[SyntaxHighlight] Plugin added successfully
```

Если видите:
```
[SyntaxHighlight] Self-check failed, syntax highlighting disabled
```
Значит, что-то сломалось — проверьте ошибки выше.

## Распространенные проблемы

### Подсветка не работает

1. **Проверьте консоль:** есть ли логи `[SyntaxHighlight] Self-check failed`?
2. **Проверьте API:** работает ли `/api/morphology/analyze`?
3. **Проверьте данные:** есть ли лог `[SyntaxHighlight] Plugin apply called, data keys: X`?

### Слова не подсвечиваются определённым цветом

1. Проверьте, что часть речи есть в `POS_COLORS`
2. Проверьте формат цвета (должен быть `#RRGGBB`)
3. Проверьте консоль на наличие `[SyntaxHighlight] No color for POS: ...`

### Редактор падает при включении подсветки

1. Проверьте логи самопроверки
2. Запустите автоматические тесты
3. Проверьте, что все импорты в `DocumentEditor.jsx` корректны

## Производительность

### Метрики

- **Анализ слова:** ~5-10ms (зависит от API)
- **Создание декорации:** <1ms
- **Перерисовка при изменении:** ~10-50ms для 1000 слов

### Оптимизация

- Анализируются только **новые** слова
- Декорации пересчитываются только при **изменении документа** или **новых данных**
- Используется дебаунс для снижения нагрузки на API

## Безопасность

### XSS защита

Все цвета валидируются перед применением:
```javascript
if (!isValidHexColor(color)) {
  console.error('Invalid color:', color);
  return null;
}
```

### Injection защита

Регулярное выражение ограничено только кириллицей и дефисами - невозможно вставить вредоносный код.
